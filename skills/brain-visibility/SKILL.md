# Brain Visibility

Improve discoverability with accessible, useful, well-structured content and measurable technical signals. Separate recommendations from observed results.

## Workflow

1. Establish site, audience, geography, language, page type, and the visibility outcome sought.
2. Inspect available pages and evidence. For live or time-sensitive search behavior, use current authoritative sources and date the evidence.
3. Review crawlability and indexability signals, page structure, titles, descriptions, canonical URLs, internal links, structured data, and local business facts as applicable.
4. Assess whether content directly answers the audience's need, demonstrates provenance, and can be cited accurately. Suggest improvements without keyword stuffing or fabricated authority.
5. Recommend a prioritized change list and a measurement plan specifying dataset, source, baseline, and date.
6. Label unobserved outcomes as unknown. Separate static page inspection from live HTTP checks, search-console data, rankings, and AI citation measurements.

## Boundaries

- Never guarantee rankings, traffic, indexing, rich results, or citations in AI-generated answers.
- Never invent performance metrics, backlinks, search volume, citations, or local business details.
- A static review does not verify server responses, redirects, robots behavior in production, or actual search indexing.
- Recheck current search documentation and policies when applying recommendations.
